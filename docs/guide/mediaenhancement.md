复刻宿主的媒体模块外观，但把**歌词同步与播放进度**换成自研引擎 —— 专治国内播放器（网易云音乐、酷狗音乐、QQ 音乐）在系统媒体接口下拿不到进度、歌词卡第一行的问题。

| 项 | 值 |
| --- | --- |
| 插件标识 | `com.nps.mediaenhancement` |
| 显示名称 | 媒体增强 |
| 当前版本 | **1.5.0** |
| 交付形态 | **单个 dll**（附 `plugin.json`，目录型分发包） |
| 宿主要求 | NotchPeninsula 现代插件契约（目标框架 `net10.0-windows10.0.19041.0`） |

::: tip 为什么要单独做这个插件
宿主自带的媒体模块依赖系统媒体接口（SMTC）上报的播放位置。实测网易云与酷狗的 SMTC
**能给出标题、艺术家与封面，但 `Timeline` 全为 0、且不允许 seek** —— 宿主因此拿不到进度，
歌词会一直停在第一行。本插件改用「真实进度源 + 自研歌词引擎」来解决这件事。
:::

## 一、安装

1. 把 `NpsMediaEnhancement.dll` 放进宿主 `plugins\` 目录；若用的是目录型分发包，
   把整个 `NpsMediaEnhancement\` 文件夹（含 `plugin.json`）放进去。
2. 启动宿主，进入**插件中心**，启用「媒体增强」。
3. 到 **设置 → 显示设置** 里勾选它，即可上岛。

::: warning 建议关闭宿主自带的媒体控制
两者外观相近，同时显示会在岛上并排出现两块媒体区域。
请在**宿主设置里关闭原生媒体内容**，只保留本插件。
:::

## 二、内置 PlayerCap（无需手动安装）

**PlayerCap**（Metabox-Nexus-PlayerCap，社区维护的本地服务）是本插件最高优先级的数据源。
插件会**自己把它装好并拉起**，你不需要手动下载：

| 环节 | 行为 |
| --- | --- |
| 复用已有副本 | 优先检查**下载文件夹与桌面**上是否已有 `Metabox-Nexus-PlayerCap.exe`，有就直接拿来用 |
| 自动下载 | 没有则从镜像下载到 `%LocalAppData%\NpsMediaEnhancement\PlayerCap\`，并校验文件大小（>5 MB）与 PE 头 |
| 下载源顺序 | 内置镜像（`github.boki.moe` → `ghfast.top` → `gh-proxy.com`，**直连**）→ GitHub 官方地址**经代理** → GitHub 官方地址**直连**兜底 |
| 后台运行 | 以无窗口方式启动，输出重定向到 `playercap.log`；已在运行则不重复启动 |
| 权限 | PlayerCap 需要**读取播放器进程内存**，因此必须以**管理员身份**运行 |

::: warning PlayerCap 需要管理员权限
若日志里出现权限相关失败，可在**设置窗口「日志」分区**里点「管理员运行」——
它会通过系统提权对话框重新拉起（此操作会弹出 UAC 提示，需要你确认）。
:::

::: info 如何确认 PlayerCap 已生效
打开**设置窗口**（详情页右上角「设置」按钮）的「播放与会话」分区，点一次「重新匹配」；
再到「日志」分区确认 PlayerCap 日志在滚动、歌词随进度正常滚动，说明链路正常。
:::

## 三、歌词与进度的来源

插件按优先级依次尝试，任何一级可用就不再往下走：

| 优先级 | 来源 | 提供什么 |
| --- | --- | --- |
| ① | **PlayerCap 服务** | 真实播放位置、行边界（当前行 / 下一行起点）、封面、频谱 |
| ② | **SMTC 时间轴** | 播放位置（仅部分播放器有效） |
| ③ | **内存进度源** | 读取播放器进程内的进度 |
| ④ | **本地外推时钟** | 按播放 / 暂停状态用本地时钟推进，兜底 |

**歌词文本**的取词顺序：**本地 LRC（强匹配）** → 网易云（落月 API 两步流程，含逐字 `yrc` 与译文）→
酷狗（官方三段链路，含 KRC 逐字）→ LRCLIB → 本地松散匹配兜底。PlayerCap 下发的歌词窗口只作取词中或失败时的兜底。

### 3.1 本地歌词（LRC 文件）

把歌词文件放进**宿主程序目录下的 `lyrics` 文件夹**（即 `NotchPeninsula.exe` 所在目录，插件启动时会自动创建），
文件名按 **`歌名 - 歌手.lrc`** 命名，分数够高时它会**绕过网络与缓存**优先使用：

| 环节 | 行为 |
| --- | --- |
| 匹配打分 | 文件名归一化（全角转半角、只留字母数字、小写）后打分：完全等于歌名 100 / 含歌名 60 / 再含歌手 +25 / 歌名与歌手顺序反过来再 +15；**≥85 直接采用**，60～84 只在网络取词失败后兜底 |
| 支持格式 | 普通逐行 `[mm:ss.xx]歌词`；也可用**增强逐字** `[mm:ss.xx]词<mm:ss.xx>词`，扫光会按字级时间推进 |
| 编码 | 依次尝试 BOM → UTF-8 → GB18030（GBK）→ Latin1，中文 GBK 歌词可直接用 |
| 目录兼容 | 旧的 `%LocalAppData%\NotchPeninsula\lyrics` 与 `%LocalAppData%\NpsMediaEnhancement\lyrics` **只读兼容**，之前放的文件仍然有效；宿主装在 Program Files 导致主目录不可写时自动退回旧位置并记一行日志 |

::: tip 本地歌词按文件自己的时间轴走
本地文件常与平台那版录音不是同一个母带（行首可能差 0.7 秒以上）。命中本地文件后，插件**整首按文件的时间轴推进**，
不再拿平台歌词的行逐行比对 —— 因此不会出现两个源来回跳导致的吞词、重扫卡顿与动画重启。
PlayerCap 为播放器烘焙的时间平移（如网易云 `-500ms`）也会被自动抵消，**本地文件「延迟 0」就是对上的**。
:::

::: tip 为什么位置与歌词来自两个源
PlayerCap 的位置与「歌曲开播那一刻」同源，是准确的；而它的歌词切分与插件歌词并不完全一致
（它会把一行拆成两行）。因此插件**以 PlayerCap 的位置和行边界为基准**，
再把逐字数据从自己的歌词里按行挂载上去 —— 这样扫光与切句始终同基，不会出现「每首歌延迟都不一样」。
:::

::: details 各播放器的已知差异
- **网易云音乐**：支持逐字歌词（`yrc`）；部分冷门曲目没有逐字数据，会回退为整行扫光。
- **酷狗音乐**：系统媒体接口**不含时间轴**（业界共识），因此依赖 PlayerCap 或内存进度源才能得到进度。
- **QQ 音乐**：系统媒体接口上报的位置是**静止快照**（不随播放推进），插件用本地时钟外推补足。
- 落月歌词接口**不支持酷狗**，酷狗歌词走酷狗官方接口。
:::

## 四、收起态

灵动岛上平时显示的是：**封面 + 歌词 + 右侧频谱条**。

| 元素 | 说明 |
| --- | --- |
| **封面** | 左侧圆角封面，高度随行高自适应（20～32）。取图按**系统媒体接口 → PlayerCap → 宿主 → 该歌曲所在软件的图标**依次兜底：前三级都拿不到时先画软件图标（等比缩到 62% 居中，不拉伸变形），封面到达后自动替换 |
| **歌词** | 垂直居中显示当前行，带逐字扫光；若有翻译或音译则显示为两行（原文 + 副行）。开启**多行歌词**后，第二行改显**下一句**，换句时整块向上推移 |
| **频谱** | 右侧实时频谱条，数据优先取宿主提供的真实频谱，其次取 PlayerCap 的频谱帧；播放中若 3 秒收不到音帧，插件会主动重连音频通道 |
| **进度条** | 岛体最底部一条发光的播放进度条，宽度只覆盖歌词区（不伸进频谱），端点随岛宽伸缩、位置按当前曲目比例；亮度随节拍轻微脉动，颜色**跟随宿主文字色**（深色 / 浅色主题都看得清） |

宽度会**即时跟随当前内容** —— 换句立刻变宽或变窄，不会出现「岛已经变短、右侧还留一块白」的迟滞。

::: tip 收起态不跟随封面配色
彩色氛围光只出现在**详情页**（可在设置窗口「频谱与律动」关闭）；收起态刻意保持克制的跟随文字色进度条与宿主同款频谱，避免岛上持续有一块彩色在动。
:::

### 4.1 交互

| 动作 | 效果 |
| --- | --- |
| **左键单击** | 打开详情页 |
| **右键单击** | 打开详情页 |
| **鼠标悬浮在歌词区** | 歌词让位，显示**上一曲 / 播放暂停 / 下一曲**三个控件；组件宽度同步收缩 |
| **双击封面** | 启动对应的音乐软件（按会话的应用标识解析，UWP 与桌面程序都支持） |
| **右键频谱条** | 打开详情页 |

::: warning 悬浮触发范围只限歌词区
在**封面**或**频谱条**上悬浮不会显示播放控件 —— 这是有意的，避免误触。

另外，组件上**其它区域的右键不会做任何事**。原因是插件为了接管「右键频谱」，
需要声明接受右键事件，宿主的默认行为（右键展开组件、或打开控制台）随之被让出。
:::

::: tip 悬浮时宽度会收缩是正常现象
悬浮态要腾出空间给三个控件，歌词会暂时让位。插件用**自算的常态宽度矩形**判定悬浮，
而不是用宿主给出的悬浮状态 —— 否则宽度收缩后光标位置落到组件外，
会产生「一缩就闪、一闪就还原」的振荡。
:::

## 五、详情页

详情页是**单页布局**，左键或右键单击收起态即可打开。页面底部有一层**封面主题色的氛围光**：
颜色取自当前封面，透明度跟着音乐响度走 —— 安静的段落淡到看不见，有旋律时才漫出来
（可在设置窗口「频谱与律动」关闭或换跟随源）。

### 5.1 页面内容

- **封面**（52×52，带 1px 描边）+ **曲名 / 歌手**
- **歌词**：当前行原文（逐字扫光）+ 副行（翻译优先，其次音译，排列方式在设置窗口选择）；
  开启多行歌词时上下各多显示 1～2 句相邻句
- **频谱带**：按设置窗口选择的样子绘制。频段采用**对数分布**（每根柱等音程宽度）并做自动增益，
  因此高低频都有起伏，不会出现「只有左半边在动」；柱子弹起快、回落柔和
- **进度条**（可点击）：轨道 + 已完成段 + 头部圆点，两端显示**已播 / 总时长**；
  点条身任意位置即跳转（播放器不支持 seek 时该操作被忽略）
- **音量滑杆**：喇叭图标 + 细轨 + 百分比，按**当前正在播放的音乐软件**调节音量
  （等价于 Windows 音量合成器里该应用那一行）；点喇叭静音，点轨道或拖拽调值；
  拿不到应用会话时整块不显示
- **控制按钮**：上一曲 / 播放暂停 / 下一曲
- **「设置」按钮**（右上角）：打开独立设置窗口（见下节）

::: tip 文字颜色会跟着真实底色变
插件会读取宿主亚克力背板的实际颜色，按**每个元素所在位置**的底色决定用深字还是浅字 ——
即使宿主开着深色主题、而岛体背后透上来的是浅色桌面，歌词与按钮也依然清晰。
:::

## 六、设置窗口

点详情页右上角的**「设置」按钮**打开。这是一个独立窗口，不依赖宿主的窗口能力：

| 区域 | 说明 |
| --- | --- |
| **自绘标题栏** | 置顶📌 / 最小化 / 最大化 / 关闭；双击标题栏最大化还原；**Esc** 关闭 |
| **窗口记忆** | 位置与置顶状态会被记住，下次打开原样恢复 |
| **窗口主题** | 「面板行为」分区顶部可选：跟随宿主 / 浅 / 深 |

### 6.1 六个分区

| 分区 | 内容 |
| --- | --- |
| **播放与会话** | 会话列表（每个正在播放的音乐软件一行：图标 + 名称 + 当前歌曲 + 三个控制按钮）、**「重新匹配」**按钮 —— 重新索取当前歌曲的全部内容（元数据、封面、播放状态、整曲歌词、当前行与位置），用于歌词与进度错位时复位 |
| **歌词与扫光** | **延迟补偿** `(−) 数值 (+)`（0.1 秒一步，点数值归零）；**歌词排列**（靠左 / 居中 / 靠右，统一管当前句、相邻句与译文）；**多行歌词**（关 / 3 行 / 5 行）；**译文对齐**（居左 / 居中 / 居右 / 拉伸 / 关闭）；**歌词切换动画**（无 / 淡入 / 上滑 / 下滑 / 缩放 / 聚焦，多行模式下停用） |
| **频谱与律动** | **频谱样式**（波形 / 竖条 / 镜像 / 圆点）；**颜色律动**（关闭 / 全局 / 人声 / 伴奏）—— 详情页底部氛围光跟哪一路响度走 |
| **面板行为** | **忽略外部鼠标**（光标移出、点别处都不收起详情页，右键仍是唯一关闭手势）；**永久显示**（详情页不自动收起）；**窗口主题** |
| **日志** | PlayerCap 日志与插件日志**双页签**；「PlayerCap 更新 / 插件更新 / 重启 PlayerCap / 管理员运行」操作按钮；「刷新」「打开文件夹」；**更新源**与**代理**两个可直接输入的字段；「Debug 日志」显示开关与「清空日志」（两击确认） |
| **高级与接入** | **MSP 接入状态**与说明（见下） |

::: tip 多行歌词与译文对齐互斥
多行模式下译文不参与排版（相邻句已占满行位），所以两者**双向联动**：
开多行会自动把译文对齐切到「关闭」；选回任意译文对齐则自动退回单行。
:::

::: tip 三种「颜色律动」跟随源怎么选
- **全局**：整帧响度，鼓点与整体起伏都在，最通用；
- **人声**：只听 344 Hz ～ 3.4 kHz，跟着唱词起伏，慢歌与清唱段落最明显；
- **伴奏**：低频与高频的组合，跟鼓、贝斯与镲片走，电子与摇滚更带感。

选「关闭」时页面底部完全不画氛围光。旧版本里那个「开 / 关」开关会自动迁移为「全局」。
:::

::: tip 「副行对齐」的参考是歌词本身
各种对齐都以**本句歌词的实际宽度**为参考，而不是面板整宽 —— 短句时译文不会被推到面板最右边。
「拉伸」按**字间距**摊满整行，不横向压扁字形；字太少时会自动退回居中，避免摊得难看。
:::

### 6.2 MSP 接入

**MSP**（Model Sensing Protocol）是宿主的实验功能（**宿主设置 → 通用设置 → MSP 接入**，默认关闭），
开启后宿主的 AI 能力可以直接读取插件提供的媒体数据。本插件注册四个工具：

| 工具 | 提供什么 |
| --- | --- |
| `lyric_current` | 当前句原文 / 译文 / 逐字时间（相对行首），附播放进度与总时长 |
| `lyric_line` | 按行号取任意一句歌词 |
| `lyric_lrc` | 整曲 LRC（`plain` 纯文本 / `words` 带字级标签） |
| `media_extra` | 媒体状态摘要：平台、PlayerCap 是否在线、歌词来源、有无逐字、时间基说明 |

设置窗口「高级与接入」会显示四种状态之一：**已启用** / **未开启**（宿主开关未打开，打开后自动补注册）/
**宿主过旧**（宿主不含 MSP 接口）/ **注册失败**（接口与开关都正常，但注册被拒，附真实原因）。

### 6.3 实况窗

同一分区还有**「显示实况窗」**开关（默认关闭）。打开后，灵动岛**左侧**会多一个圆形气泡：

| 部分 | 内容 |
| --- | --- |
| 外圈进度弧 | 当前歌曲播放进度；暂停时停在当前进度；没有歌曲或时长不可信时转为不确定态旋转 |
| 内圈 | 当前封面（应用图标兜底时等比缩到 62%；没有封面时画音符） |

- **左右键点气泡**展开的就是同一个媒体详情页 —— 不需要另做一套页面。
- 收起态主岛内容（歌词 / 频谱 / 进度条）完全不受影响，气泡是独立的第二展示面。
- 宿主**设置 → 实况窗管理**里可以单独关掉本插件的气泡；关掉时气泡立即挂起，主岛照常显示，
  重新打开后继续更新进度。
- 同屏最多 8 个气泡，放不下时最老的几个不绘制。

## 七、日志与自更新

日志查看与更新操作都在**设置窗口「日志」分区**（见 6.1）。两个页签分别对应：

| 页签 | 内容 |
| --- | --- |
| **PlayerCap 日志** | PlayerCap 服务的运行日志；操作按钮：PlayerCap 更新 / 重启 PlayerCap / 管理员运行 |
| **插件日志** | 插件自身日志（WARN 橙 / ERROR 红，可开 Debug 显示）；操作按钮：插件更新 |

通用功能：刷新、打开日志文件夹、「清空日志」（两击确认，两路日志各自清）。

::: tip 更新源与代理直接在页面底部输入
「更新源」「代理」两个**可编辑字段**：点击进入编辑，输入后回车保存、Esc 取消、点字段外任意处提交。
PlayerCap 的更新源留空用内置镜像；代理填 `主机:端口`（也可以带 `http://` 前缀）。
**本地回环请求（PlayerCap 的数据链路）始终直连，不会被代理影响。**
:::

## 八、插件自更新

插件会检查自身是否有新版本（以插件市场为准）：

1. 发现新版本后**在后台静默预下载**（运行中的 exe 无法覆盖自身，所以先下载为 `.new`）；
2. 下次启动前由插件完成替换；
3. 设置窗口「日志」分区会**区分**「PlayerCap 更新」与「插件更新」两类信息，不会混为一谈。

## 十、常见问题

**Q：歌词不显示 / 只有歌词没有进度？**
按顺序检查：

1. 确认**播放器正在播放**（暂停时收起态仍显示上一句，但不会推进）；
2. 打开**设置窗口「日志」分区**看 PlayerCap 那一路：若提示权限不足，点「管理员运行」；
3. 看插件日志里有没有「换歌过渡：已忽略与当前位置不符的行」这类正常诊断行；
4. 到「播放与会话」分区点一次**「重新匹配」**。

**Q：歌词整体超前或滞后？**
在设置窗口「歌词与扫光」分区用 `(−)` / `(+)` 微调（0.1 秒一步），点中间数值归零。
补偿会**同时作用于行内扫光和行切换**，所以扫光与切句保持同步。

**Q：暂停之后扫光退回行首？**
已修复：暂停会**冻结在当前行的当前进度**，不会退回开头。
（若暂停时你手动拖动进度条或换歌，则按新位置重新取行。）

**Q：歌词切换很快的歌里，扫光没跑完就切走了？**
插件会按 PlayerCap 给出的**本行真实长度**校准扫光速度，使其在本行结束前跑完；
间奏这类偏长的行不做加速，避免被拉成慢动作。

**Q：换歌时岛上还显示上一首的歌词？**
插件对新歌的行做了**位置自洽校验**（并留一个短暂的过渡窗口），
PlayerCap 在换歌期间继续推上一首的行会被忽略，不会把旧歌词贴回岛上。

**Q：频谱不动 / 暂停后消失？**
暂停后不再有新帧，插件会让最后一帧**停在原地**，这是有意的，不是卡死。
播放中若频谱定格，说明音频通道还连着却不再送帧 —— 插件带**断流看门狗**：播放中 3 秒收不到音帧就强制重连音频通道，
一般 1～3 秒内恢复，恢复时插件日志会记一条「频谱已恢复」。
若长时间为空，先确认 PlayerCap 在运行；仍为空时详情页会回退绘制宿主自己的频谱。

**Q：封面一直是软件图标？**
封面按「系统媒体接口 → PlayerCap → 宿主 → 软件图标」四级兜底，落到最后一级说明前三级都没有图。
最常见的原因是**系统媒体控制被关掉**（设置 → 蓝牙和其他设备 → 媒体控制，或音量面板上方的媒体控件里看不到这首歌）——
插件的会话、元数据与播放控制都以系统媒体会话为入口；此状态下封面仍可由 PlayerCap 补上，
但「重新匹配」与播放控制会因拿不到会话而失效。

**Q：详情页底部的氛围光看不到，或者一直很淡？**
按顺序看：① 设置窗口「频谱与律动」的「颜色律动」是否为「关闭」（默认关闭）；
② 安静段落与间奏时它是**故意不可见**的 —— 透明度由响度驱动，没有旋律就不画，这是设计而非故障；
③ 封面是纯灰 / 黑白时取不到主题色，会退回宿主的强调色；
④ 明暗会按卡片底色自动适配，深色封面在黑色实底上会被提亮，不会糊进背景。

**Q：详情页总是被自动收起，想让它一直留在屏幕上？**
设置窗口「面板行为」的**永久显示**关掉自动收起；**忽略外部鼠标**则让「光标移出」与「点别处」都不收起，
两者可以只开一个。无论开哪个，右键关闭都照常有效。

**Q：设置窗口打不开，或者看得见却点不动？**
1.3.x 曾存在两个已知根因（窗口线程异常被静默吞掉、热重载后窗口类名冲突），1.4.0 已修复 ——
遇到时请先**禁用再启用插件**（宿主不监听插件目录，覆盖 dll 后也必须这样才加载新版本）；
若仍有问题，插件日志会记录窗口创建与点击命中的完整诊断链路。

**Q：音量滑杆调了没反应？**
1.4.0 已修复多音频会话的调值问题（同一播放器常同时挂两路会话，旧版只改到空置的一路）。
现在按「一个应用一行」语义对该软件**所有会话逐路生效**并回读真实值。
若滑杆整块不显示，说明插件拿不到该软件的应用会话（如刚启动、或系统音频服务异常）。

**Q：深色主题下歌词 / 按钮颜色发白发灰？**
插件按**实际底色**决定文字深浅：读取宿主亚克力背板截图后逐元素取色，
即使宿主主题与岛体背后实际颜色不一致也会用对颜色。若仍异常，
可在设置窗口「面板行为」把窗口主题手动指定为浅或深。

**Q：更新下载失败？**
日志会写明**当前代理 + 当前源 + 最后一次失败原因**。常见原因是网络需要代理而插件拿不到 ——
在设置窗口「日志」分区底部手填「代理」即可。镜像本身通常是可用的。

**Q：酷狗音乐没有歌词？**
酷狗走酷狗官方三段链路（搜索 → 取词候选 → 下载）。若拉不到词，多为网络原因或该曲目在酷狗侧没有资源；
装上 PlayerCap 后由插件统一调度会更稳。

**Q：翻译 / 音译没有显示？**
副行优先取翻译，没有翻译时取音译，两者都没有时只显示原文单行。
酷狗侧不带翻译数据，插件会**跨源补译文**（借网易云同曲的翻译，时间轴容差 500 ms 内合并）。

**Q：双击封面没有启动软件？**
插件按会话的应用标识解析可执行文件，少数以特殊方式安装的程序可能解析不到 —— 这种情况会静默失败。

**Q：文字里出现方块 / 缺字？**
插件对文本使用「宿主自定义字体优先、逐字符回退」的策略，正常不会出现方块。
若大面积出现，请检查宿主设置里的自定义字体文件是否有效。

## 十一、已知边界

- **落月歌词接口不支持酷狗**，酷狗歌词必须走酷狗官方链路；
- **酷狗的系统媒体接口不含时间轴**，进度必须依赖 PlayerCap 或内存进度源；
- **PlayerCap 需要管理员权限**才能读取播放器进程内存；不装或权限不足时，
  进度精度会退到 SMTC / 内存源 / 本地外推三档；
- 部分**网易云冷门曲目没有逐字数据**，歌词会回退为整行扫光；
- 详情页尺寸**只在打开时测量一次**（宿主契约限制），因此详情页打开期间若换歌、歌词变宽，
  超长歌词会按省略号截断；关闭重开会按新宽度重新测量；
- 插件**只读** PlayerCap 的位置，所有播放控制（上一曲 / 播放暂停 / 下一曲）仍走系统媒体接口；
- **系统媒体控制关闭**（或播放器不上报会话）时拿不到媒体会话：封面与歌词可由 PlayerCap 兜底，
  但播放控制、双击封面启动软件与「重新匹配」会失效 —— 这是系统能力的边界，不是插件取舍。
