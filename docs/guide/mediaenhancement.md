复刻宿主的媒体模块外观，但把**歌词同步与播放进度**换成自研引擎 —— 专治国内播放器（网易云音乐、酷狗音乐、QQ 音乐）在系统媒体接口下拿不到进度、歌词卡第一行的问题。

| 项 | 值 |
| --- | --- |
| 插件标识 | `com.nps.mediaenhancement` |
| 显示名称 | 媒体增强 |
| 交付形态 | **单个 dll**（附 `plugin.json`，目录型分发包） |
| 宿主要求 | NotchPeninsula 现代插件契约（目标框架 `net10.0-windows10.0.19041.0`） |

::: tip 为什么要单独做这个插件
宿主自带的媒体模块依赖系统媒体接口（SMTC）上报的播放位置。实测网易云与酷狗的 SMTC
**能给出标题、艺术家与封面，但 `Timeline` 全为 0、且不允许 seek** —— 宿主因此拿不到进度，
歌词会一直停在第一行。本插件改用「真实进度源 + 自研歌词引擎」来解决这件事。
:::

## 一、安装

1. 把 `NpsMediaEnhancement.dll` 放进宿主 `plugins\` 目录；若用的是目录型分发包，
   把整个 `NpsMediaEnhancement\` 文件夹（含 `plugin.json`）放进去。
2. 启动宿主，进入**插件中心**，启用「媒体增强」。
3. 到 **设置 → 显示设置 → 显示内容** 里勾选它，即可上岛。

::: warning 建议关闭宿主自带的媒体控制
两者外观相近，同时显示会在岛上并排出现两块媒体区域。
请在**宿主设置里关闭原生媒体内容**，只保留本插件。
:::

## 二、前置条件：PlayerCap（强烈推荐）

插件的**最高优先级数据源**是一个独立的本地服务 **Metabox-Nexus-PlayerCap**（Go 编写，由社区维护）：

| 项 | 值 |
| --- | --- |
| 项目地址 | <https://github.com/VTB-LINK/Metabox-Nexus-PlayerCap> |
| 监听地址 | `127.0.0.1:8765`（仅本机回环） |
| 运行方式 | **以管理员身份运行** |

它提供歌词、真实播放进度、逐字时间轴、封面与频谱，覆盖网易云、酷狗、QQ 音乐等主流播放器。
插件以 300 ms 的节奏轮询它，并通过一条本地 WebSocket 接收 512 点频谱帧。

**不装它也能用**——插件内置了完整的回退链路（见下节）。但装了之后，进度是**播放器直读的真实值**，
不再需要估算，酷狗也能拿到进度。

::: info 如何确认 PlayerCap 已生效
打开详情页的**页 2**：若「重新匹配播放进度」按钮显示为
**「进度由播放器直读 · 无需匹配」**，说明 PlayerCap 已在线。
:::

## 三、歌词与进度的来源（多级回退）

插件按优先级依次尝试，任何一级可用就不再往下走：

| 优先级 | 来源 | 提供什么 | 何时使用 |
| --- | --- | --- | --- |
| ① | **PlayerCap 服务** | 真实进度、整首歌词、逐字时间轴、封面、频谱 | 服务在线时（推荐） |
| ② | **SMTC 时间轴** | 播放位置（仅部分播放器有效） | PlayerCap 离线 |
| ③ | **内存进度源** | 读取播放器进程内的进度的估算值 | ② 无效时 |
| ④ | **本地外推时钟** | 按播放 / 暂停状态用本地时钟推进 | 兜底 |

**歌词文本**同样有多级来源：PlayerCap 的整首歌词 → 插件自行拉取（网易云走落月 API 两步流程、
酷狗走官方三段链路、再兜底 LRCLIB）。换歌后会给 PlayerCap 约 1 秒的拉词窗口，
它没给词时插件才自己取，之后 PlayerCap 拿到词会自动覆盖回来。

::: details 各播放器的已知差异
- **网易云音乐**：支持逐字歌词（`yrc`）；部分冷门曲目没有逐字数据，会回退为整行扫光。
- **酷狗音乐**：系统媒体接口**不含时间轴**（业界共识），因此**依赖 PlayerCap 或内存进度源**才能得到进度。
- **QQ 音乐**：系统媒体接口上报的位置是**静止快照**（不随播放推进），插件用本地时钟外推补足。
- 落月歌词接口**不支持酷狗**，酷狗歌词走酷狗官方接口。
:::

## 四、收起态

灵动岛上平时显示的是：**封面 + 歌词 + 右侧频谱条**。

| 元素 | 说明 |
| --- | --- |
| **封面** | 左侧圆角封面，高度随行高自适应（20～32） |
| **歌词** | 垂直居中显示当前行，带逐字扫光；若有翻译或音译则显示为两行（原文 + 副行） |
| **频谱** | 右侧实时频谱条，数据优先取宿主提供的真实频谱，其次取 PlayerCap 的频谱帧 |

宽度会**自适应当前内容**（不读宿主预算），上限 760。

### 4.1 交互

| 动作 | 效果 |
| --- | --- |
| **左键单击** | 打开详情页 |
| **右键单击** | 打开详情页 |
| **鼠标悬浮在歌词区** | 歌词让位，显示**上一曲 / 播放暂停 / 下一曲**三个控件；组件宽度同步收缩 |
| **双击封面** | 启动对应的音乐软件（按会话的应用标识解析，UWP 与桌面程序都支持） |
| **右键频谱条** | 打开详情页 |

::: warning 悬浮触发范围只限歌词区
在**封面**或**频谱条**上悬浮不会显示播放控件 —— 这是有意的，避免误触。

另外，组件上**其它区域的右键不会做任何事**。原因是插件为了接管「右键频谱」，
需要声明接受右键事件，宿主的默认行为（右键展开组件、或打开控制台）随之被让出。
:::

::: tip 悬浮时宽度会收缩是正常现象
悬浮态要腾出空间给三个控件，歌词会暂时让位。插件用**自算的常态宽度矩形**判定悬浮，
而不是用宿主给出的悬浮状态 —— 否则宽度收缩后光标位置落到组件外，
会产生「一缩就闪、一闪就还原」的振荡。
:::

## 五、详情页

详情页是**一页里两个分页**，底部两个指示点切换。

### 5.1 页 1 · 播放详情

- **封面**（56×56）+ **曲名 / 歌手**
- **双行歌词**：当前行原文（逐字扫光）+ 副行（翻译优先，其次音译）
- **频谱带**：按你在页 2 选择的样式绘制
- **控制按钮**：上一曲 / 播放暂停 / 下一曲
- **歌词延迟行**（右下角）：`(−) 数值 (+)`，以 0.1 秒为步进微调歌词时间轴；**点数值本身即可归零**。
  非零时旁边会显示一个强调色圆点，提示补偿正在生效

### 5.2 页 2 · 全部会话

- **会话列表**：每个正在播放的音乐软件一行 —— 软件图标 + 软件名 + 当前歌曲名 + 三个控制按钮（上一曲 / 播放暂停 / 下一曲）
- **频谱样式选择器**：标题行右侧的四个胶囊，点选即切换（见下节）
- **「重新匹配播放进度」按钮**（底部居中）：用于歌词与进度错位时重新定位。
  它有四种状态反馈：

| 状态 | 含义 |
| --- | --- |
| 可点击 | 空闲，点一下即开始重新匹配 |
| 匹配中 | 正在定位，按钮显示进度 |
| 匹配完成 | 已完成，按钮短暂提示 |
| **进度由播放器直读 · 无需匹配** | PlayerCap 在线，进度本身就是播放器给出的真实值，无需匹配 |

::: tip 什么时候需要点「重新匹配」
你手动拖动过播放器的进度条、或歌词整体错位时。若 PlayerCap 在线则不需要 ——
那种情况下进度是直读的，点了也不会有额外效果（按钮会直接告诉你无需匹配）。
:::

## 六、四种频谱样式

在详情页**页 2** 的标题行右侧选择，四种样式共用同一份频谱数据：

| 样式 | 外观 |
| --- | --- |
| **波形** | 平滑对称波形，带上方描边与渐变填充，中线一条淡基准线 |
| **竖条** | 底部对齐、向上生长的密集竖条（经典 EQ 观感） |
| **镜像** | 以中线上下对称伸缩，中间一条基准线 |
| **圆点** | 每列一个圆点，纵向位置随电平起伏 |

选择会被记住（写入宿主设置键 `SpectrumStyle`），插件重载后仍然沿用。

::: tip 暂停时频谱会停住而不是消失
频谱数据来自 PlayerCap 的音频帧，暂停后不再推送新帧。插件会让最后一帧**停在原地**，
而不是把整条清空 —— 这样暂停时画面是静止的，不会突然空掉。
:::

## 七、设置项

插件不提供自建的配置窗口，两项设置通过宿主的设置接口持久化，落在注册表：

| 设置键 | 默认值 | 说明 |
| --- | --- | --- |
| `SpectrumStyle` | `0` | 频谱样式：`0` 波形 / `1` 竖条 / `2` 镜像 / `3` 圆点。一般直接在详情页页 2 里点选即可 |
| `LyricDelayOffset` | `0` | 歌词延迟补偿（秒），范围 `-10.0` ～ `+10.0`，步进 0.1。一般直接在详情页页 1 右下角调整 |

```
HKCU\SOFTWARE\NotchPeninsula\Plugin.com.nps.mediaenhancement.SpectrumStyle
HKCU\SOFTWARE\NotchPeninsula\Plugin.com.nps.mediaenhancement.LyricDelayOffset
```

## 八、常见问题

**Q：岛上什么都没有？**
① 确认播放器正在播放（暂停时不显示内容）；② 确认插件的显示开关已在
「设置 → 显示设置 → 显示内容」里勾选；③ 确认宿主自带的媒体内容已经关闭，避免两者互相干扰。

**Q：歌词一直停在第一行 / 完全不滚动？**
这通常是进度源失效。按顺序检查：

1. 启动 PlayerCap（若已装），看详情页页 2 的按钮是否变成「进度由播放器直读 · 无需匹配」；
2. PlayerCap 没装或没启动时，点一次「重新匹配播放进度」让插件重新定位；
3. 确认播放器本身在正常播放（不是暂停、也不是缓冲中卡住）。

**Q：歌词整体超前或滞后？**
在详情页页 1 右下角用 `(−)` / `(+)` 微调歌词延迟（0.1 秒一步），
点中间那个数值即可归零。这是**按曲目生效的观感补偿**，用于弥补不同播放器上报时间的系统性偏差。

**Q：歌词对，但进度条 / 时长不对？**
部分播放器不提供总时长，插件以**歌词时间轴**作为量程。若这首歌的歌词起止时间与音频实际长度不符，
进度条的比例就会偏。这属于播放器数据源的限制，不是插件计算错误。

**Q：酷狗音乐没有歌词？**
酷狗走的是酷狗官方三段链路（搜索 → 取词候选 → 下载），旧接口已不可用。
若拉不到词，通常是网络原因或该曲目在酷狗侧没有歌词资源；装上 PlayerCap 后由其统一提供会明显更稳。

**Q：翻译 / 音译没有显示？**
副行会优先取翻译，没有翻译时取音译。两者都没有时只显示原文单行。
酷狗侧不带翻译数据，插件的做法是**跨源补译文**（借网易云同曲的翻译，时间轴容差 500 ms 内合并）。

**Q：悬浮时显示播放控件，但鼠标一移过去控件就消失了？**
新版本已修复（触发范围按「歌词区与控件组宽度的较大者」计算）。
若仍遇到，请反馈版本号与复现步骤。

**Q：双击封面没有启动软件？**
插件按会话的应用标识解析可执行文件。少数以特殊方式安装的程序可能解析不到 ——
这种情况会静默失败，不弹提示。

**Q：文字里出现方块 / 缺字？**
插件对文本使用「宿主自定义字体优先、逐字符回退」的策略：画不出的字会回退到系统字体，
因此正常不会出现方块。若大面积出现，请检查宿主设置里的自定义字体文件是否有效。

## 九、已知边界

- **落月歌词接口不支持酷狗**，酷狗歌词必须走酷狗官方链路或由 PlayerCap 提供；
- **酷狗的系统媒体接口不含时间轴**，进度必须依赖 PlayerCap 或内存进度源；
- 部分**网易云冷门曲目没有逐字数据**，歌词会回退为整行扫光（功能正常，只是没有逐字效果）；
- 详情页尺寸**只在打开时测量一次**（宿主契约限制），因此详情页打开期间若换歌、歌词变宽，
  超长歌词会按省略号截断；关闭重开会按新宽度重新测量；
- 插件**只读** PlayerCap 的播放位置，所有播放控制（上一曲 / 播放暂停 / 下一曲 / 点进度跳转）
  仍走系统媒体接口。
